# Проверка Career Quest для жюри

[← README](../README.md) · [Чек-лист ТЗ](REQUIREMENTS.md) · [Архитектура](ARCHITECTURE.md)

Сначала выполните [инструкцию запуска](../README.md#быстрый-запуск). Основной сценарий занимает около 5 минут; импорт и HR можно проверить отдельно. Здесь описано фактическое поведение основной ветки, а не список будущих функций.

## Перед демонстрацией

- Открыт `http://localhost:3000`, профиль загрузился, кнопка «Исследовать город» активна.
- Для воспроизводимого расчёта используйте исходный стартовый набор и `LLM_PROVIDER=mock`. При проверке настоящего AI подключите ключ отдельно и смотрите режим итогового ответа.
- Проверочная дата приложения — **2026-10-01**, независимо от календарной даты компьютера.
- Основной сотрудник — **E0028, Akmaral Ismailova, Backend Engineer, Middle → Senior**. Выбор аватара не меняет навыки и грейд.
- Примеры чисел ниже относятся к исходному набору до изменения цели, импорта или выполнения новых активностей.

## Основной сценарий

| Шаг | Действие жюри | Ожидаемый результат |
|---|---|---|
| 1. Профиль | В лобби выбрать E0028 → «Дальше: цель» | Цель Senior подставлена из карьерной лестницы; видны требования, дефициты и первые шаги |
| 2. Город и герой | «Исследовать город» → «Сам исследую» → **C** | Лист героя с ролью, грейдом, целью, навыками, историей и личным XP; требования к Senior: **4/16** |
| 3. Рекомендация | Закрыть лист → «Наставник» → написать «Предложи следующий шаг» | До трёх карточек с объяснением; в «Как получен ответ» доступны шаги и результаты инструментов. Режим ответа обозначает онлайн, офлайн или fallback |
| 4. Обоснование | Сопоставить карточки с историей и требованиями | Уже завершённые EV_006/EV_007 не предлагаются. EV_009 понижен из-за брошенных сертификаций, но может остаться третьим кандидатом |
| 5. Выполнение | Выбрать шаг → открыть его площадку через карту или «Мой план» **J** → «Взять и начать» / «Выполнить задание» | Открывается демо-практика: Python/TypeScript либо три рабочие ситуации, подсказки и проверка решения |
| 6. Прогресс | Решить → «Проверить решение» → после успешной проверки «Засчитать выполнение» | Видны реальные изменения навыков и прогресс требований; завершённый шаг отмечен. Повторное засчитывание обычного события не даёт второй прирост |
| 7. Следующий шаг | «К наставнику» → снова запросить рекомендацию | Подбор учитывает новую историю и навыки. Самостоятельный повторный вызов наставника после завершения не запускается |

**Быстрая демонстрация города:** войдите в офис через кнопку или **E**, смените этаж, нажмите **V** для первого лица. Зажатая мышь поворачивает взгляд; **V** возвращает обзор. В офисах есть коллеги и точки занятий. Карьерный грейд и физический номер этажа — разные сущности.

**Примерить другую роль:** «Примерить роль» → сравнить две траектории. Просмотр не меняет профиль; кнопка «Выбрать эту цель» сохраняет новую цель. После этого значения эталонного сценария E0028 будут другими.

## Проверка импорта жюри

1. Откройте [страницу импорта](http://localhost:3000/upload), доступную также из лобби.
2. Выберите `employees.json`, `activity_history.csv` или оба файла сразу.
3. Нажмите «Загрузить». Получите число записанных профилей и новых строк истории либо конкретную ошибку валидации.
4. Нажмите «В город» и выберите добавленного сотрудника. Получите рекомендации тем же способом, что для исходных профилей.

JSON использует оболочку `{"employees": [...]}`, а не голый массив. Роли, грейды и навыки должны быть из загруженного каталога. Пример **собственного вымышленного профиля**, совместимого со схемой стартового кита:

```json
{
  "employees": [
    {
      "employee_id": "JURY_DEMO_001",
      "full_name": "Проверочный участник",
      "department": "Backend Development",
      "role": "Backend Engineer",
      "grade": "Middle",
      "manager_id": null,
      "hire_date": "2025-01-01",
      "tenure_months": 21,
      "work_format": "hybrid",
      "preferred_language": "ru",
      "career_goal": {"target_role": "Backend Engineer", "target_grade": "Senior"},
      "skills": {"SK_SYSTEM_DESIGN": 2},
      "last_review_date": "2026-09-01"
    }
  ]
}
```

CSV требует все десять столбцов (порядок можно менять). Например, при одновременной загрузке с этим профилем:

```csv
record_id,employee_id,event_id,date,due_date,status,completion_pct,score,feedback_rating,assigned_by
JURY_R001,JURY_DEMO_001,EV_006,2026-09-15,,completed,100,90,5,self
```

Это пример формата, а не замена трём проверочным профилям жюри. Он использует существующий `event_id` из стартового каталога; без соответствующего события в каталоге импорт отклоняется.

Правила, которые можно проверить:

- Совпадающий `employee_id` **заменяет весь профиль**, новый ID добавляет сотрудника.
- Обе формы проверяются до записи: ошибка одного файла не должна частично применить другой.
- Повтор содержательно одинаковой строки истории пропускается, даже при новом `record_id`.
- Занятый `record_id` с другим содержимым, неизвестный сотрудник/навык/событие и некорректные даты дают ошибку.
- Статусы: `completed`, `in_progress`, `dropped`, `no_show`, `declined`, `overdue`; `assigned_by`: `self`, `manager`, `hr`.
- `due_date`, `score`, `feedback_rating` могут быть пустыми. `manager_id` — `null` или ID другого существующего/одновременно загружаемого сотрудника.
- Импорт событий и каталога навыков через этот экран не предусмотрен.
- Импорт и новый прогресс живут до перезапуска серверного процесса; исходные файлы `data/` не перезаписываются.

## Проверка HR

1. Откройте [HR-обзор](http://localhost:3000/hr). Войдите: **`admin` / `admin`** (латиницей) → «Открыть рабочее пространство».
2. На вкладке «Обзор компетенций» примените фильтр отдела/грейда или найдите сотрудника по имени, роли, ID. Проверьте дефициты навыков, текущие и требуемые уровни. Раскройте **«Подробный HR-отчёт · навыки и участие в обучении»**: здесь слабые навыки по отделам, «Без следующего шага» с причинами и участие по мероприятиям.
3. Выберите сотрудника → «Создать план обучения» → «Подобрать до 3 шагов» либо выберите события вручную, укажите сроки → «Сохранить черновик».
4. Во вкладке «Планы обучения» найдите карточку плана и нажмите «Опубликовать». Публикация сама по себе не начисляет навыки.
5. Для проверки добровольного участия во вкладке «Доступ и роли» создайте демонстрационный аккаунт «Сотрудник», привяжите профиль и задайте пароль длиной от 10 символов. Войдите этим аккаунтом: собственный опубликованный план можно принять или отложить через «Не сейчас».

**Различайте метрики:** «Нужен план обучения» означает отсутствие действующего HR-плана; «Без следующего шага» в подробном отчёте — отсутствие подходящей рекомендации движка. Подробный отчёт учитывает выбранные фильтры и доступные пользователю отделы.

## Проверка через API

Команды ниже используют Bash и `curl`, запущенный сервер на 3000 и исходный стартовый набор.

```bash
curl -fsS http://localhost:3000/api/profile/E0028
curl -fsS http://localhost:3000/api/recommend/E0028
```

Поток наставника (может вызвать внешний API, если включён онлайн-режим):

```bash
curl -N -sS -H 'Content-Type: application/json' \
  -d '{"employeeId":"E0028","messages":[{"role":"user","content":"Предложи следующий шаг"}]}' \
  http://localhost:3000/api/mentor
```

В финальном событии смотрите `mode`: `offline`, `openai` или `fallback`. Наличие интеграции в исходниках не подтверждает успешный вызов провайдера в конкретном окружении.

## Если запуск не получился

| Симптом | Что проверить |
|---|---|
| «Нет data/ и не найден архив» | Указать `DATASET_ZIP` в командной строке или положить четыре файла непосредственно в `data/` |
| `unzip: command not found` | Распаковать архив вручную либо установить `unzip` в своей среде |
| Порт 3000 занят | Остановить свой предыдущий сервер; запасной запуск `npm run dev -- --port 3001`, затем открыть этот порт |
| Лобби ещё без профиля | Дождаться первой компиляции; открыть `/api/profile/E0028` и посмотреть сообщение об отсутствующих данных |
| Наставник перешёл в fallback | Проверить выбранный режим, ключ, доступность модели и сеть; расчётный подбор доступен через `/api/recommend/E0028` |
| Нет подходящих карточек | Проверить цель, prerequisites, историю и покрытие разрывов каталогом; пустой подбор допустим, неподходящий курс не подставляется |
| Числа отличаются от таблицы | Профиль/цель/история изменены в текущем процессе; таблица относится к исходному набору |
| После рестарта пропал импорт | Повторно загрузить профили и историю — основной store в памяти |
| 3D работает медленно | Использовать кнопки карты/панелей для основного сценария; проверить WebGL и аппаратное ускорение браузера |

Обновление страницы сбрасывает клиентскую сессию интерфейса, но не серверную историю. Перезапуск сервера сбрасывает основной store; HR-планы и аккаунты сохраняются отдельно в локальном файле.
