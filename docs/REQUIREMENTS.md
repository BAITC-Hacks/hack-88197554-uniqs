[← README](../README.md) · [Как проверить](DEMO.md) · [Архитектура](ARCHITECTURE.md)

Проверка подготовлена по реализации основной ветки, включая коммит `03a89b6`, и заданию Career Quest трека Halyk Bank. Планы из VISION и наличие неиспользуемой функции сами по себе не означают выполненный пункт.

**Обозначения:** ✅ реализовано и доступно в основном сценарии; 🟡 частично или требует условия; ⬜ не реализовано / результат не подтверждён. Наличие ✅ не является обещанием промышленной готовности или оценкой жюри.

## Правила данных и расчёта

- [x] Цель из `career_goal`; без неё — следующий грейд текущей роли. У Lead без цели следующая ступень отсутствует.
- [x] Навыки берутся на дату `last_review_date`; completed после ревью до расчётной даты доначисляются хронологически.
- [x] Прирост ограничен `max_level`, текущий уровень не уменьшается.
- [x] Для рекомендаций исключаются обязательные, уже пройденные, недоступные по текущим роли/грейду/prerequisites и бесполезные для цели события.
- [x] Регулярный клуб EV_036 допускает повтор в другой день; в один расчётный день повторный completed идемпотентен.
- [x] `no_show`, `dropped`, `declined` по типу и формату снижают оценку; предыдущие completed её повышают.
- [x] Расчёт не привязан к E0028; этот ID используется только как начальный пример в интерфейсе.
- [x] Необязательный шаг можно отложить через «Не сейчас» без прироста навыков.
- [x] Нет публичного рейтинга сотрудников. Личный XP не начисляется за обязательные активности.

История меняет score, а не вводит абсолютный запрет на похожий формат. Например, EV_009 у исходного E0028 остаётся третьим кандидатом с отрицательным score. Игровой уровень не равен должностному грейду; выполнение требований означает готовность обсуждать повышение, а не автоматическое кадровое решение.

## Ограничения из ТЗ

| Статус | Пункт | Фактическая граница |
|---|---|---|
| ✅ | Объяснимость расчёта | Факторы и их веса доступны; рост навыков вычисляет движок, не модель |
| ✅ | Добровольность | «Не сейчас» в активностях, принятие/отказ от опубликованного HR-плана |
| ✅ | Запуск одной командой | После клонирования и получения архива: `npm ci && DATASET_ZIP="…" npm run dev -- --port 3000` |
| 🟡 | Разграничение employee / HR | Роли, отделы и разрешения применяются к `/api/hr/*`. API города, профилей, прогресса и импорта не имеют сквозного разграничения |
| 🟡 | Приватность / внутренний контур | Стартовый кит не хранится в Git; в городе можно выбирать чужой демонстрационный профиль. Для реальных HR-данных текущая сборка не предназначена |
| ⬜ | Отклик UI ≤2 с и рекомендация ≤10 с | Полный замер на целевом окружении не проведён. Таймаут LLM 8.5 с — лишь ограничение запроса, не доказательство общего SLA |
| 🟡 | Видимый процесс работы агента | События передаются через SSE. В чате во время запроса видна текущая стадия, полный разбор инструментов — после ответа; панель следующего шага показывает вызовы во время запроса |

## Что проверено при подготовке документации

- На работающем сервере `/api/profile/E0028` вернул System Design **3**, цель Senior и **4/16** закрытых требований.
- `/api/recommend/E0028` вернул **EV_010 → EV_037 → EV_009**, по шесть факторов; оценки **1.5 / 1 / −0.5**.
- Демо-вход `admin/admin` и `/api/hr` ответили HTTP 200; отчёт вернул заполненные `weakSkills`, `noStep`, `participation`. Проверочная сессия после чтения закрыта.
- Каталог практики `/api/venues/practice?eventIds=EV_012,EV_013` ответил HTTP 200 и вернул обе задачи.
- Управление камерой и доступность приложения на 3000 проверены в браузере при поставке переключателя.
- Онлайн-вызов модели и задержки на хостинге не выдаются за успешно проверенные результаты. Подключение трёх HR-срезов подтверждено кодом действующего API и компонента подробного отчёта.
