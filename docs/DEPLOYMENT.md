# Деплой Career Quest

[← README](../README.md#деплой) · [Сценарий проверки](DEMO.md) · [Архитектура](ARCHITECTURE.md)

Инструкция не привязана к конкретному провайдеру. Подходит VPS или управляемый **Node.js Web Service** с долгоживущим процессом, доступом к файлам и доменом. Здесь описана конфигурация текущего приложения; публикация на конкретном хостинге этой инструкцией не подтверждается.

## 1. Выбрать среду

| Требование | Зачем |
|---|---|
| Node.js **24** | Next.js и встроенная трансформация TypeScript в практических заданиях; проверенная локальная версия — 24.11.0 |
| npm и Bash | Установка зависимостей и команда подготовки данных |
| `unzip`, если используется архив | Распаковка стартового кита; при готовой `data/` не требуется |
| **Один** процесс / одна реплика | Профили, новый прогресс и HR-сессии хранятся в памяти процесса |
| Записываемая файловая система | Next.js использует локальные файлы; HR создаёт `src/features/hr/.local/` |
| HTTPS-домен и поддержка потоковых HTTP-ответов | UI, API, HR-cookie и события наставника SSE |

Не выбирайте режим «Static Site» / GitHub Pages: в приложении есть серверные API. Обычное serverless-размещение с отдельными эфемерными функциями также не соответствует текущему хранению состояния. Для запуска на такой архитектуре сначала потребуется изменить хранение; в этой инструкции используется обычный Node.js-сервер.

Next.js поддерживает самостоятельный хостинг через `next start`; перед ним нужен `next build`. При собственном сервере домен обслуживается через reverse proxy, который направляет запросы к Node.js. [Документация Next.js](https://nextjs.org/docs/app/guides/self-hosting)

## 2. Подготовить исходники и данные

Подключите репозиторий `BAITC-Hacks/hack-88197554-uniqs`, ветку `main`. Если хостинг получает код через GitHub, ему нужен доступ к этому репозиторию. Рабочая директория всех команд — корень проекта.

**Клонирования репозитория недостаточно:** `data/` исключена из Git. До старта сервиса обеспечьте один из вариантов:

- Передайте четыре файла `employees.json`, `events.json`, `skills.json`, `activity_history.csv` непосредственно в `<корень проекта>/data/`.
- Передайте архив на сервер через доступный механизм файлов/диска и задайте `DATASET_ZIP` как путь к этому **серверному файлу**. Это не URL для скачивания и не путь на вашем ноутбуке. Скрипт ожидает файлы внутри `case_1/career_quest_dataset/` архива.

На управляемом хостинге файлы можно подключить через диск/volume или загрузить в runtime-окружение. Выбирайте сервис, где один из этих способов доступен: одной переменной `DATASET_ZIP` без самого файла недостаточно. Если build и runtime выполняются раздельно, убедитесь, что данные доступны именно запущенному серверу.

Стартовый набор ограничен условиями хакатона. Публичное постоянное демо размещайте с собственными синтетическими данными той же схемы либо с разрешением организаторов на выбранный способ использования стартового набора. Архив, `.env` и содержимое HR-хранилища не добавляйте в Git и папку `public/`.

## 3. Настройки управляемого хостинга

| Поле | Значение |
|---|---|
| Root directory | Корень репозитория |
| Node version | `24` в настройках runtime хостинга |
| Install command | `npm ci --include=dev` |
| Build command | `npm run build` |
| Start command | `bash scripts/setup-data.sh --if-missing && npm run start -- --hostname 0.0.0.0` |
| Replicas / processes | `1` |

Если отдельных Install/Build полей нет, используйте одну Build-команду:

```bash
npm ci --include=dev && npm run build
```

Dev-зависимости нужны **на этапе сборки**, даже если `NODE_ENV=production`. `build` сам не распаковывает архив. Подготовка данных включена в Start-команду: при заполненной `data/` скрипт просто продолжает запуск.

Если платформа принимает executable и аргументы вместо shell-строки, передайте Start-команду через `sh -c` либо выполните подготовку данных её pre-start-механизмом. Обычный запуск после подготовки файлов — `npm run start -- --hostname 0.0.0.0`.

В `package.json` нет поля `engines`: версию Node нужно явно выбрать на стороне хостинга. В `next.config.ts` также не включён `output: "standalone"`: не рассчитывайте на наличие `.next/standalone/server.js`.

## 4. Переменные окружения

| Переменная | Значение / назначение |
|---|---|
| `NODE_ENV` | `production` для работающего сервиса |
| `PORT` | Порт, выданный платформой; `next start` читает его автоматически. Без переменной используется 3000 |
| `DATASET_ZIP` | Путь к доступному на сервере архиву; необязателен, если все четыре файла уже в `data/` |
| `LLM_PROVIDER` | `mock` для воспроизводимого офлайн-демо; `openai` для онлайн-режима |
| `OPENAI_API_KEY` | Серверный секрет, нужен только онлайн-режиму |
| `OPENAI_MODEL` | Доступная аккаунту модель; значение по умолчанию в коде — `gpt-6-sol` |

Переменные задаются в настройках сервиса, а не коммитятся в репозиторий. `DATASET_ZIP` должен быть доступен оболочке до запуска: `setup-data.sh` не читает `.env.local`. Для серверного ключа не используйте префикс `NEXT_PUBLIC_`.

## 5. Пример запуска на VPS

После установки Node 24, Git, Bash и `unzip` выполните на сервере:

```bash
git clone https://github.com/BAITC-Hacks/hack-88197554-uniqs.git
cd hack-88197554-uniqs
npm ci --include=dev
```

Передайте разрешённый архив в соседнюю с репозиторием папку, затем:

```bash
DATASET_ZIP="../career_quest_dataset.zip" bash scripts/setup-data.sh --if-missing
npm run build
NODE_ENV=production LLM_PROVIDER=mock npm run start -- --hostname 0.0.0.0 --port 3000
```

Последняя команда запускает сервер в текущем терминале. Для постоянной работы сохраните её как команду сервиса в менеджере процессов/служб вашей среды; рабочая папка должна оставаться корнем репозитория. Подключите HTTPS-домен через reverse proxy к выбранному порту. Если используете порт платформы, уберите `--port 3000` и передайте `PORT` через окружение.

При переносе собранного проекта сохраняйте `.next/`, `public/`, `node_modules/`, конфигурацию и метаданные проекта, `data/` и путь для записи `src/features/hr/.local/`. Самый простой вариант — сборка и запуск в одном полном checkout.

## 6. Диск, перезапуски и поток наставника

- HR-аккаунты и планы записываются в `<корень проекта>/src/features/hr/.local/workspace.json`. Для сохранения между пересозданиями сервиса подключите постоянный диск именно к этой директории. Переменной `HR_DATA_DIR` в текущем коде нет.
- Исходные файлы читаются из `<корень проекта>/data/`; переменной `DATA_DIR` также нет. При каждом новом размещении они должны быть доступны в этом пути.
- **Постоянный диск не сохраняет основной прогресс:** новые выполнения, импортированные профили и цели находятся в памяти. После рестарта они сбрасываются; данные жюри нужно импортировать снова. HR-планы сохраняются отдельно и могут ссылаться на ещё не загруженные профили.
- Не включайте несколько реплик или cluster-workers: они будут иметь разные профили, историю и сессии. Редеплой также завершает текущие сессии и сбрасывает состояние в памяти.
- Для `/api/mentor` прокси должен пропускать `text/event-stream` без накопления всего ответа. При использовании nginx отключите buffering для этого маршрута, иначе стадии наставника появятся только в конце. [Streaming при self-hosting Next.js](https://nextjs.org/docs/app/guides/self-hosting#streaming-and-suspense)

Опубликованный демо-адрес не делает эту сборку системой для реальных HR-данных: общий доступ к API города/импорта ещё демонстрационный, а `admin/admin` — открытая демо-учётная запись. Эти границы описаны в [чек-листе ТЗ](REQUIREMENTS.md).

## 7. Проверить размещение и передать ссылку

На выданном хостингом HTTPS-домене проверьте:

1. `/` — загружаются город и список сотрудников, активна кнопка входа.
2. `/api/profile/E0028` — при использовании исходного кита возвращается JSON, а не ошибка отсутствия данных. Для собственного набора используйте существующий в нём ID.
3. `/hr` — вход `admin/admin`, компетенции и подробный HR-отчёт открываются.
4. Наставник — видны стадии запроса и итоговый режим `offline`, `openai` или `fallback`.
5. `/upload` и выполнение практики — доступны по [сценарию жюри](DEMO.md).

После проверки добавьте реальный URL в начало README и в форму сдачи, если в ней есть соответствующее поле. Адрес `localhost:3000` указывает на компьютер открывающего страницу и не является ссылкой на опубликованное демо.
