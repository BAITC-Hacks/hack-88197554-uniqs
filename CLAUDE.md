# Правила для всех агентов (Claude Code, Codex)

Хакатон, 5 часов, двое людей. Цель одна: работающее демо в UI. Всё остальное не имеет значения.

## Готово значит
1. Руками проверяет пользователь. Агенту достаточно, чтобы страница открывалась или эндпоинт отвечал; долгие самопроверки и скриншоты не нужны. Сломалось — пользователь скажет, чиним дальше.
2. `./scripts/check.sh` зелёный (typecheck + lint, ~10 сек). Один прогон в конце задачи, не после каждой правки.
3. Три строки в ответе: что изменил · как посмотреть · что не сделано.

## Жёсткие лимиты
- Одна ошибка чинится максимум 2 раза. Не вышло — остановись и напиши, что именно не работает.
- Одна задача = один коммит, до 30 минут. Больше — раздели и сделай первую часть.
- Новая зависимость только если без неё задача не решается. Скажи об этом в ответе.
- Файлы вне своей зоны не трогай. Нужно — остановись и скажи.

## Не делаем и не предлагаем
Тесты (кроме одного smoke, если попросят), health-чеки, логирование, CI, Docker, auth, error boundaries, i18n, адаптив, пустые состояния и скелетоны, рефакторинг работающего кода, конфиги «на будущее», README пока не попросят.

## Скорость
- Внешний сервис или API: сначала мок с фикстурой, реальный вызов вторым шагом.
- UI: одна библиотека компонентов (shadcn/ui + Tailwind, иконки lucide), десктоп 1440, одна цветовая схема. Не дизайнить с нуля. 3D-город — только `@react-three/fiber` + `@react-three/drei`, без других 3D-библиотек и физики.
- Не исследуй репо «для контекста»: карта и команды ниже. Читай только файлы задачи.
- Не спрашивай подтверждений на очевидное. Спроси, только если задача противоречит этому файлу.

## Проект
- Что строим: Career Quest (трек Halyk Bank). AI-наставник подбирает сотруднику 1–3 следующих шага развития и объясняет выбор минимум по трём факторам. После отметки «выполнено» двигается прогресс, у HR есть срез по проседающим навыкам. Ядро — качество и объяснимость рекомендации. Главный экран — «Город карьеры»: один общий low-poly 3D-город. 8 башен отделов (этажи = грейды), площадки обучения по типам активностей, юрта AI-наставника. Персонаж = выбранный сотрудник, панели мест = экраны продукта.
- Все цели и приоритеты P0–P3: docs/VISION.md. Демо-сценарий: docs/DEMO.md. Контракт между фичами: docs/DECISIONS.md. Задание скелета: prompts/skeleton.md.
- Стек: Next.js (App Router) + TypeScript + Tailwind + shadcn/ui + three.js (`@react-three/fiber`, `@react-three/drei`). Данные в памяти процесса, без БД. LLM через `src/lib/llm.ts`: по умолчанию мок, провайдер подключим, когда появится ключ.
- Запуск: `npm install && npm run dev` → http://localhost:3000 (`predev` сам распакует датасет, если `data/` пуста).
- Данные: `data/` — стартовый кит (employees.json, events.json, skills.json, activity_history.csv), только чтение, **не в git** (`scripts/setup-data.sh`, в worktree копирует `scripts/setup-worktree.sh`). Дата «сегодня» = `2026-10-01`.
- shadcn здесь на Base UI (`@base-ui/react`), не Radix: перед использованием компонента загляни в `src/components/ui/<имя>.tsx`. `cn` импортируется из `@/lib/utils`.
- Карта (А — мозг, Б — экраны):
  - `src/lib/` — типы, store, llm, sse, world, client-store (скелет, дальше заморожено)
  - `src/features/engine/` — расчёт навыков, разрывов и рекомендаций, прогресс (А)
  - `src/features/mentor/` — агент-наставник: цикл, инструменты, стрим, панель юрты (А)
  - `src/features/character/` — лист персонажа и журнал квестов (Б)
  - `src/features/venues/` — панели площадок, «Выполнено» / «Не сейчас» (Б)
  - `src/features/office/` — панель башни отдела: лестница и прогресс этажа
  - `src/features/hr/` — HR-дашборд `/hr` (Б)
  - `src/features/upload/` — загрузка профилей и истории (Б)
  - `src/features/city/` — 3D-сцена: земля, камера, персонаж, места города, модели в `public/models/`
  - `src/features/hud/` — оверлей: выбор сотрудника, быстрое перемещение, панели
  - Владельцы фич города и остальных панелей — после скелета, по списку из VISION

## Правила данных (ловушки датасета)
- Навыки в профиле указаны на дату `last_review_date`. Активности со статусом `completed` после неё надо доначислить: +`gain`, но не выше `max_level`.
- Цель: `career_goal`, а если он `null` — следующий грейд своей роли. Требования берутся из `role_profiles`, `critical_skills` — главное для повышения.
- Не рекомендовать: `mandatory`, уже `completed` (кроме регулярного клуба EV_036), чужие роли и грейды, непройденные `prerequisites`, активности без пользы (навык уже ≥ `max_level` или ≥ требования).
- `no_show` / `declined` / `dropped` по похожему типу или формату — сигнал против. Рекомендация по одному полю запрещена.
- Жюри грузит свои профили в том же формате, поэтому всё считаем из store, а не из захардкоженных id.
- Нельзя: публичные рейтинги сотрудников и очки за обязательные активности. Участие добровольное: у каждого шага есть «Не сейчас».

## Параллельная работа
- Параллельно в других папках работают другие агенты. Ты владеешь только папкой своей фичи из задачи: `src/features/<имя>/` (UI и серверный код вместе), плюс тонкие файлы-реэкспорты `src/app/<имя>/page.tsx` и `src/app/api/<имя>/.../route.ts` своей фичи.
- Общие файлы заморожены: `src/lib/*`, `src/app/layout.tsx`, `src/app/page.tsx`, package.json, `data/`. Регистрация — одна строка в конец реестра: панель здания → `src/panels.ts`, ссылка → `src/nav.ts`, объект в сцене (пасхалка) → `src/features/city/extras.ts`, модель → `src/features/city/models.ts`. Нужно менять общий тип или добавить зависимость: остановись и напиши.
- Смежная фича ещё не готова: работай против мока по общим типам, не жди.
- Готово → сам влей в main и запушь (пользователь разрешил): `git fetch origin && git merge origin/main` → `./scripts/check.sh` зелёный → `git push origin HEAD:main`. Push отклонён — повтори fetch, merge, push. Без force-push, чужие ветки не трогать. Интегратора нет.
- Оркестратор (главная сессия Claude) не запускает Workflow: только отдельные фоновые агенты на UI и механику, сам остаётся на связи с пользователем.
- Dev-сервер только на порту из задачи.

## Worktree
Ты, скорее всего, в git worktree, а не в основном checkout.
- `.env` и зависимостей может не быть: git их не копирует. Сначала `./scripts/setup-worktree.sh`, не создавай `.env` сам и не коммить его.
- Ветка занята этим worktree. Не делай `git checkout` на другую ветку, особенно на main.
- Путь к репо у каждого worktree свой. Не пиши абсолютные пути в код и конфиги.

## Агент внутри продукта
Один цикл. Инструментов столько, сколько нужно демо, но каждый должен быть виден в демо и не падать вживую. Шаги и вызовы инструментов стримятся в UI. Ошибка инструмента показывается, а не роняет всё.
